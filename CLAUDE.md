## Project Overview

This project is a feature-rich, AI-powered Quran study application called "Open Quran Reader". It's a web-based tool built with **React** and **TypeScript**, using **Vite** for the development environment.

The application allows users to read the Quran, listen to recitations, view translations, and engage in deep analysis of the text. It leverages the **Gemini API** for AI-powered features like natural language search and verse explanations (Tafseer).

### Core Features:

- **Quran Reader:** A clean, modern interface for reading the Quran in both Uthmani and simple scripts.
- **Audio Player:** Listen to verse-by-verse recitations from a wide selection of renowned reciters.
- **Translations:** Supports multiple translations in various languages.
- **AI Search:** A powerful search feature that uses the Gemini API to find relevant verses based on natural language queries.
- **AI-Powered Tafseer:** Get concise, easy-to-understand explanations for any verse, generated by the Gemini API.
- **Word Analysis:** In-depth analysis of Quranic words, including root identification, phrase searching, and Abjad calculation. This is powered by a combination of a local data source (`quran-roots.json`) and the [Quran.com API](https://quran.com/labs/api).
- **Note-Taking:** Users can take notes on individual verses, which are saved in the browser's local storage.
- **Customization:** Users can customize the reading experience with settings for font size, theme (light/dark), and more.

### Tech Stack

- **React 19** — UI framework
- **TypeScript 5.8** — strict typing, target ES2022/ESNext
- **Vite 6** — build tool and dev server
- **Tailwind CSS** — utility-first styling (inline classes)
- **@google/genai** — Gemini API for AI features
- **@xyflow/react** — ReactFlow for NodeReader canvas
- **lucide-react** — icon library
- **Bun** — package manager and runtime
- **Vitest** — unit testing, **Playwright** — E2E testing

### Architecture

- **Flat structure:** No `src/` directory; components at root level
- **Single entry point:** `App.tsx` orchestrates all state and child components
- **Path alias:** `@/*` maps to project root
- **State management:** React hooks, no external state library
- **Persistence:** Browser localStorage for settings, notes, and bookmarks
- **Client-side only:** No backend server; all data fetched from external APIs
- **Services:**
  - `quranService.ts`: Quran data from `api.alquran.cloud` and `everyayah.com`
  - `geminiService.ts`: AI features via Gemini API
  - `analysisService.ts`: Word/root analysis
  - `letterAnalysisService.ts`: Arabic letter analysis
  - `textSanitizer.ts`: Text normalization

### Domain Context

- **Quran terminology:** Surah (chapter), Ayah (verse), Tafseer (explanation/exegesis)
- **Arabic text:** Uthmani script (traditional) and Simple script options; RTL rendering required
- **Root analysis:** Arabic words share trilateral roots (e.g., "كتب" = k-t-b)
- **Verse keys:** Format is "surah:ayah" (e.g., "1:1" = Al-Fatiha verse 1)

### External Dependencies

- **Gemini API** (`@google/genai`) — AI-powered search and explanations
- **api.alquran.cloud** — Quran chapters, verses, and translations
- **everyayah.com** — Verse-by-verse audio recitations
- **Quran.com API** — Word-level data and root analysis
- **quran-roots.json** — Local data source for Arabic root lookups

## Building and Running

### Prerequisites:

- **[Bun](https://bun.sh/)** — package manager and runtime

### Setup:

1.  **Install Dependencies:**

    ```bash
    bun install
    ```

2.  **Set API Key:**
    Create a `.env.local` file in the root of the project and add your Gemini API key:
    ```
    GEMINI_API_KEY=your_api_key_here
    ```

### Running the Application:

- **Development Mode:**

  ```bash
  bun run dev
  ```

  This will start a development server, typically at `http://localhost:3000`.

- **Production Build:**

  ```bash
  bun run build
  ```

  This will create a `dist` directory with the optimized production build of the application.

- **Preview Production Build:**
  ```bash
  bun run preview
  ```
  This will serve the production build locally for testing.

## Performance-First Guidelines

Performance is the highest priority. Every dependency, module, and abstraction must justify its existence.

- **No unnecessary libraries**: Only add a dependency when building it from scratch would be significantly worse
- **Lazy load all view modes**: Use `React.lazy()` for any component that represents an alternate view (FocusMode, NodeReader, etc.)
- **Separate vendor chunks**: Add `manualChunks` entries in `vite.config.ts` for new heavyweight dependencies so they don't bloat the initial bundle
- **Memoize**: Use `React.memo()` on custom nodes, `useMemo` for layout calculations, `useCallback` for handlers
- **Pure layout functions**: Keep layout/positioning logic in pure functions — testable, memoizable, no React dependency

## Testing (Test-Driven Development)

This project follows **Test-Driven Development (TDD)** practices. All changes must pass the `gates` command before being merged.

### Gates Command

The `gates` command runs all quality checks in sequence:

```bash
bun run gates
```

This runs:

1. **TypeScript type checking** (`bun run typecheck`)
2. **ESLint linting** (`bun run lint`)
3. **Prettier formatting check** (`bun run format:check`)
4. **Unit tests with 80% coverage** (`bun run test:unit`)
5. **E2E tests** (`bun run test:e2e`)

### TDD Workflow

**Before implementing any new feature:**

1. Write failing tests first (unit and/or E2E)
2. Run `bun run gates` to confirm tests fail
3. Implement the feature
4. Run `bun run gates` to confirm all tests pass
5. Commit changes

### Test Structure

```
__tests__/
├── unit/
│   ├── services/     # Unit tests for services
│   └── components/   # Unit tests for React components
├── e2e/              # Playwright E2E tests
└── setup.ts          # Test setup and mocks
```

### Test Commands

| Command                   | Description                                    |
| ------------------------- | ---------------------------------------------- |
| `bun run gates`           | Run all quality checks (required before merge) |
| `bun run test`            | Run all tests                                  |
| `bun run test:unit`       | Run unit tests with coverage                   |
| `bun run test:unit:watch` | Run unit tests in watch mode                   |
| `bun run test:e2e`        | Run E2E tests                                  |
| `bun run test:e2e:ui`     | Run E2E tests with UI                          |

### Coverage Requirements

- **Minimum 80% coverage** for branches, functions, lines, and statements
- Coverage reports are generated in the `coverage/` directory
